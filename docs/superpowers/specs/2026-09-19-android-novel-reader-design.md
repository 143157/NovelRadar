# Android 全网小说阅读器设计规格

- 日期：2026-09-19
- 状态：用户已确认
- 项目名称：小说雷达
- 目标平台：Android 8.0 及以上

## 1. 背景与目标

本项目基于现有 SoNovel 的配置驱动书源思想，开发一款可直接安装到 Android 手机上的小说阅读器。第一版不依赖自建服务器，搜索、解析、阅读和下载均在设备上完成。

“全网搜书”在本项目中的明确含义是：应用并发搜索所有已启用且当前可访问的书源，将同一本书的多来源结果聚合展示，并允许用户导入更多符合 SoNovel JSON 结构的书源。它不表示无限制扫描整个互联网，也不包含绕过验证码、登录验证、Cloudflare 或其他网站访问保护。

### 1.1 首版目标

1. 提供可安装的 Android APK。
2. 支持多书源并发搜索、结果聚合、去重和排序。
3. 支持书籍详情、目录、在线阅读、书架和阅读进度。
4. 支持章节缓存及整本后台下载、暂停、继续、重试和断点恢复。
5. 支持导入、校验、启停和测试 SoNovel JSON 书源。
6. 在单个书源失败时保持其他来源可用。

### 1.2 非目标

首版不实现账号体系、云同步、听书、评论社区、应用商店发布、EPUB/PDF/TXT 导出、Legado 规则兼容或服务端聚合搜索。

## 2. 已确认的产品决策

| 项目 | 决策 |
|---|---|
| 平台 | Android APK |
| 架构形态 | 纯手机端，无自建后端 |
| 技术路线 | Kotlin + Jetpack Compose 原生 Android |
| 书源格式 | SoNovel JSON，并允许用户导入 |
| 离线能力 | 章节缓存和整本下载 |

## 3. SoNovel 搜索方法提炼

现有 SoNovel 采用配置驱动解析，规则将请求构造与页面解析从代码中解耦。移动端将保留以下核心机制，并替换不适合 Android 的实现：

1. `search.url`、`method` 和 `data` 构造 GET 或 POST 搜索请求。GET 规则在 URL 中替换 `%s`；POST 规则将 SoNovel 的对象式 `data` 解析为表单字段。关键词在写入 URL 或表单时按 UTF-8 百分号编码，避免直接拼接。
2. `search.result` 定位每条搜索结果，再通过 `bookName`、`author`、`category`、`latestChapter`、`lastUpdateTime`、`status` 和 `wordCount` 提取字段。
3. `book`、`toc`、`chapter` 规则依次解析详情、目录和正文。
4. CSS Selector 为主要解析方式；XPath 作为兼容路径。
5. `@js:` 后缀先提取内容，再对字符串 `r` 执行受限脚本转换。
6. `pagination` 与 `nextPage` 支持搜索、目录和章节翻页。
7. `filterTxt`、`filterTag`、段落标签规则负责正文净化和分段。
8. 多书源搜索后按标准化书名和作者聚合，保留每个来源及其状态。

原 SoNovel 使用 Java 21 虚拟线程和 GraalVM JavaScript；Android 版本分别改为 Kotlin 协程和嵌入式 QuickJS 运行时。具体依赖版本在实施时锁定，但不得开放 Java/Android 对象桥接。

## 4. 总体架构

应用采用分层、单向数据流架构。

```text
Jetpack Compose UI
        ↓
ViewModel / UI State
        ↓
Use Cases（搜索、详情、目录、阅读、下载、书源管理）
        ↓
Repositories
   ├── Source Engine（规则引擎）
   ├── Room（元数据与进度）
   ├── Chapter File Store（正文文件）
   └── WorkManager（后台下载）
        ↓
OkHttp / Jsoup / XPath / Sandboxed Script Runtime
```

### 4.1 模块边界

#### UI 层

负责页面渲染、导航、用户输入和状态展示，不直接构造网络请求或解释书源规则。

#### 业务层

包含职责单一的用例：聚合搜索、加载详情、获取目录、读取章节、加入书架、保存进度、创建下载任务、切换来源和管理书源。

#### 书源引擎

负责规则校验、请求构造、字符集识别、HTML 解析、字段转换、分页、正文净化及站点错误分类。书源引擎通过稳定接口返回标准化领域模型，UI 不感知具体站点规则。

#### 持久化层

Room 保存书籍、来源映射、章节元数据、书架、阅读进度和下载任务；章节正文以独立文件原子写入，数据库只保存路径、校验信息和状态。

## 5. 核心组件

### 5.1 书源注册与校验

- 首次启动导入应用内置的 SoNovel 兼容规则。
- 用户可从本地文件导入 JSON 规则。
- 导入前检查 JSON 结构、必需字段、URL 协议、选择器格式和脚本长度。
- 每条规则具有稳定 ID、显示名称、启用状态、健康状态和最近测试结果。
- 重名规则不静默覆盖：以规则 ID 判断更新，以名称冲突提示用户选择。

### 5.2 聚合搜索

- 读取全部启用书源，为每个来源启动受限并发任务。
- 每个来源单独设置超时、重试与速率限制。
- 结果以流式状态返回，页面无需等待所有来源完成。
- 书名先进行 Unicode、空白、标点和常见括号后缀标准化，再与标准化作者共同生成聚合键。
- 完全匹配优先，其次为书名相似度；不同作品不得只因书名相近而错误合并。
- 聚合结果保留所有来源，展示可用来源数量和各来源状态。

### 5.3 详情、目录与来源切换

- 详情页显示封面、书名、作者、简介、更新状态、当前来源和可选来源。
- 切换来源后重新获取该来源目录，不覆盖其他来源的目录快照。
- 阅读中来源失效时，使用书名、作者、章节序号和标准化章节名寻找备用章节。
- 自动匹配只给出建议；跨来源切换必须向用户显示来源变化，低置信度匹配必须由用户确认。

### 5.4 阅读器

- 支持分页和纵向滚动两种模式。
- 支持字号、行距、页边距、亮度跟随或独立调节，以及日间、纸张、夜间主题。
- 自动保存书籍、来源、章节 ID、章节序号和段落/页内位置。
- 优先读取已下载正文，其次读取章节缓存，最后请求网络。
- 下一章可按设置预取，但不得无上限占用存储空间。

### 5.5 离线下载

- WorkManager 承担可恢复后台任务，并使用前台通知显示长任务进度。
- 每本书只有一个有效整本下载任务，重复操作复用或恢复现有任务。
- 下载按书源限流，章节完成后立即持久化检查点。
- 支持暂停、继续、取消、失败章节重试和应用重启后恢复。
- 取消任务只停止未完成工作；已下载章节保留，用户可另行删除。

### 5.6 书源管理

- 列表展示启用状态、协议、最近响应时间、最近成功时间和失败原因。
- 支持导入、启用、停用、删除用户规则和单源测试。
- 内置规则可停用，不可直接修改；用户可复制为自定义规则后编辑文件再导入。
- HTTP 旧书源默认停用，用户阅读风险提示后才可开启。

## 6. 页面与导航

底部导航固定为四项：书架、搜书、下载、设置。

### 6.1 书架

展示封面、书名、最近阅读章节、阅读百分比和检测到的更新。首屏突出“继续阅读”。

### 6.2 搜书

顶部为固定搜索框；结果按书聚合，并显示作者、最新章节、来源数量和搜索进度。用户可展开查看各来源的响应状态。

### 6.3 书籍详情

提供加入书架、开始阅读和整本下载三个主操作。目录支持正序/倒序、章节搜索和来源切换。

### 6.4 阅读器

正文为唯一视觉焦点。点击正文中央唤起工具栏，提供目录、亮度、字体、主题和更多设置。

### 6.5 下载管理

按书显示完成比例、当前速度、失败章节数和任务状态，提供暂停、继续、重试和取消。

### 6.6 设置与书源管理

包含阅读默认值、缓存上限、下载网络限制、HTTP 旧源开关、书源导入和健康检查。

## 7. 数据模型

核心实体如下：

- `Book`：规范化书籍身份、书名、作者、封面和简介。
- `BookSource`：一本书在某个书源中的详情 URL、来源状态和更新时间。
- `Chapter`：来源内章节 ID、序号、标题、URL 和本地正文状态。
- `ShelfEntry`：加入时间、最近阅读时间和更新提示状态。
- `ReadingProgress`：书籍、来源、章节、章节序号及页内位置。
- `DownloadTask`：目标书籍、来源、任务状态、总数、完成数和失败数。
- `SourceRule`：规则 JSON、启用状态、来源类型、协议与健康信息。

跨来源章节不共享数据库主键，以避免目录差异造成覆盖；通过可计算的匹配信息建立临时映射。

## 8. 关键数据流

### 8.1 搜索

```text
关键词
→ 读取启用规则
→ 协程限流并发请求
→ 各来源按规则解析
→ 字段标准化
→ 去重与多来源聚合
→ 持续更新搜索页面
```

### 8.2 阅读

```text
选择章节
→ 查询已下载文件
→ 查询缓存
→ 必要时请求当前来源
→ 解析与净化正文
→ 原子写入缓存
→ 展示并持续保存进度
```

### 8.3 整本下载

```text
创建任务
→ 获取或复用目录快照
→ 分批、限流下载章节
→ 每章解析/净化/原子写入
→ 更新检查点与通知
→ 对失败章节执行退避重试
→ 完成或保留可恢复状态
```

## 9. 错误处理与降级

- 搜索来源错误分为网络超时、HTTP 错误、字符集错误、规则解析失败、站点验证和未知错误。
- 单源失败仅更新该源状态；至少一个来源有结果时，搜索整体视为可用。
- 所有请求具有超时和取消能力，页面退出后不保留无意义的前台搜索任务。
- 下载采用指数退避并限制最大重试次数；失败章节单独记录，不重复下载成功章节。
- 章节正文写入临时文件并校验后重命名，避免中断产生半文件。
- 数据库升级必须提供迁移；迁移失败不得静默清空书架或进度。
- 磁盘空间不足时暂停下载并保留检查点，不自动删除用户内容。

## 10. 安全与合规边界

- `@js` 在无 Java/Android 对象桥接的隔离运行时中执行，只接收并返回字符串。
- 脚本设置执行超时、输入大小、输出大小和内存上限；超限只禁用该规则任务。
- 导入规则不能读取本地文件、通讯录、设备标识或自行创建网络请求。
- 应用不提供绕过验证码、登录、付费墙、Cloudflare 或其他访问控制的能力。
- 应用不内置小说正文；用户仅可访问其有权访问的公开内容，界面提供书源来源标识。
- 日志默认不记录 Cookie、查询参数中的敏感值或完整正文。

## 11. 测试策略

### 11.1 单元测试

- 规则 JSON 解析、迁移与校验。
- GET/POST 模板和关键词编码。
- CSS/XPath 字段提取、分页、正文分段与过滤。
- `@js` 隔离、超时和大小限制。
- 书名/作者标准化、结果聚合与章节匹配。

### 11.2 集成测试

- 使用保存的 HTML 样本覆盖现有规则的搜索、详情、目录和正文解析。
- 使用 MockWebServer 覆盖重定向、GBK/UTF-8、超时、重试、限流、分页和错误状态。
- 验证 Room、正文文件、下载检查点和 WorkManager 的协作。

### 11.3 UI 与端到端测试

- Compose 页面状态：空态、加载、部分成功、全部失败和离线状态。
- 搜索到阅读的主路径，以及整本下载的暂停、恢复和重启恢复。
- 在模拟器及至少一台 Android 真机安装可安装签名 APK 进行冒烟测试。
- 活跃书源只做补充性在线冒烟测试；稳定回归以固定 HTML 样本为准。

## 12. 首版验收标准

1. 使用本地开发签名生成的 Release APK 可在 Android 8.0 及以上设备安装和启动；分发签名与应用商店发布不在首版范围内，签名文件不得提交到版本库。
2. 应用可并发搜索所有启用且可访问的书源，逐步展示结果并聚合同书多来源。
3. 单个书源超时或解析失败不影响其他来源。
4. 用户能完成搜索、查看详情和目录、加入书架、在线阅读、恢复进度的完整流程。
5. 用户能整本下载，暂停后继续，并在应用重启后恢复任务和进度。
6. 无网络时，已下载章节可以完整阅读。
7. 用户能导入有效 SoNovel JSON 规则；无效或危险规则得到明确拒绝原因。
8. 自动化测试覆盖规则引擎、聚合、持久化、下载恢复和关键 UI 状态。

## 14. 后续演进

在首版稳定后，可按需求增加 Legado 规则适配、听书、EPUB 导入/导出、局域网传书、云同步、可选聚合后端和 iOS 客户端。上述功能不影响首版模块边界。
