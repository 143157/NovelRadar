# Paragraph first-line indentation repair

The user approved on 2026-10-15: both reading modes indent each real paragraph's first line by two Chinese-character widths; wrapped lines and a paragraph continued on another page/chunk do not indent again. Only presentation changes: original chapter bytes, UTF-16 positions, character counts and saved bookmarks stay unchanged. Rebuild and deliver a separately named debug test APK after verification.

Diagnosis: ChapterCleaner removes line-start HTML whitespace, while ReaderScreen supplies only font size/line height and both renderers display raw substrings. Writing spaces into cached content would change hashes and offsets, so it is rejected. A global first-line style alone would incorrectly indent a paragraph continued at a chunk/page boundary.

Use a shared display model for an original UTF-16 slice. Preserve the stored text and original ranges exactly, and use paragraph TextIndent(firstLine = 2.em, restLine = 0.em) at genuine paragraph starts. Use the same display model for paging measurement and final drawing. Keep titles, palette, existing gestures, bounded window, gate and settings unchanged. No settings/schema/source/cache migration or network behavior changes.

Quality review of the initial candidate confirmed a Compose 1.12.1 constraint: each separate ParagraphStyle range produces a native paragraph, so a range containing a terminal newline introduces an extra empty final line. A single style range covering multiple native newlines avoids duplicate separation but cannot give only an initial continuation paragraph a different first-line indent.

The corrected display model therefore uses at most two fragments per slice. A slice starting at a genuine paragraph boundary remains one Text with a single 2.em style over the exact original substring, including all internal newlines. A continuation starts with a 0.em fragment through the first newline (excluding that separator from the fragment's drawn text), followed, if needed, by a single 2.em fragment containing the remaining original substring. The Column boundary consumes that one separator once; subsequent newlines and blank paragraphs remain native text. Each fragment keeps its original source range; composite layout maps all visible line positions and restores back to original UTF-16 offsets. No spaces, zero-width characters, source normalization or offset rewriting are allowed. End-of-slice newlines and empty tails must be explicitly covered by layout/page-fit regressions.

Verification covers beginning-of-chapter, multiple paragraphs, empty/blank lines, continuation slices, supplementary Unicode, exact original text and ranges; compile actual Compose layout regressions for both modes.
