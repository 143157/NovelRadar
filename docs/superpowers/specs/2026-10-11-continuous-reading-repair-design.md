# 自动连续跨章、目录进度与切章性能修复设计

- 日期：2026-10-11（Asia/Shanghai）
- 基线：`b979626`，应用代码 `eace59b`，用户测试的第二个 APK。
- 用户已选择：自动连续跨章，目录跟随阅读，保留阅读进度。
- 补充确认：本章按字数计算进度，兼显章节位置；自动缓存接下来的内容，沿用默认两章预读和已有网络选择。
- 范围：优先修复用户实测反馈；不同时加入安全换源、账号、听书或其他未完成发布功能。

## 已确认的问题与证据

用户确认滚动和分页两种模式均会看到跨章正文，但没有后续章节标题，目录仍停留在原章；下载与切章普遍约需十秒。当前 `SourceEngine.chapter` 遍历分页链接，最多取二十页；它不检查后续页面是否属于另一章，只保留第一次解析的标题，随后把所有正文连接成同一个 `ChapterPage`。阅读器、缓存和下载因此仍使用最初的章节 ID。

2026-10-11 主控实际运行现有 `SourceEngineTest.chapterPaginationStopsAtTwentyPages`：退出码 0，JUnit 为一例、零失败、零错误。该样本提供二十个不同章节标题，却断言只返回第一章标题并包含第二十份正文，证明旧测试也接受了错误的跨章拼接。这是诊断证据，不是修复已经通过的证据。后续必须先增加正确的失败回归测试，再修改生产代码。

预读在切章时会被取消，可能丢弃正在完成的目标章请求；下载另有逐源限速和文件校验。十秒延迟不能全部归因于一个因素，也不能仅通过缩短超时或增加并发宣称解决。

## 1. 章节抓取边界

本章分页与下一章是两种不同动作。正文抓取可以拼接同一章节的分页，但不能把另一个目录章节的正文存到当前章节 ID 下。

- 结合当前目录中其他章节的 URL、分页链接语义和解析后的章节标题检查边界。已知下一章 URL 或明确的“下一章”链接应在请求前停止；标题证明已跨章时不得追加该页正文。
- 合法的同章第二页、第三页仍需完整保留，包括常见页码标题后缀；不能用“只抓第一页”掩盖问题。
- 对不能确认的页面保守处理并返回明确状态，不推断未验证的章节归属。保留现有循环、重定向、二十页和正文大小限制。
- HTTP 明文选择、TLS、验证页、危险规则、取消能力和逐源限流不因本次修复降低。
- 书籍身份键、章节 ID 的 URL 哈希规则以及不同来源的独立目录不变。

## 2. 连续阅读与实际可见进度

连续阅读由阅读器协调多个独立章节，而不是让抓取器把它们变成一个巨大字符串。每章保留自己的 ID、目录序号、标题、正文和字符位置。连续正文窗口保持有界，不能把整本书装入内存。

### 滚动阅读

滚动接近章末时准备下一章，进入下一章后继续滚动并显示新章节标题，不要求点“下一章”。追加正文不得把当前视口跳回章首。当前目录章节和进度由实际可见的章节及段内字符位置决定；仅仅预读完成不能提前把进度移动到下一章。

### 分页阅读

末页继续向前翻时进入下一章，从第一页显示其标题；向后阅读和手动选章仍可用。字号、模式改变或恢复位置本身不能触发自动跨章。目录、顶部章名和保存的位置来自同一个真实章节状态，不把多章当成同一章的页面。

### 目录与持久化

- 阅读中打开目录时标出当前章节，并定位到该章节。
- 返回详情目录或书架时，以同一来源的真实阅读位置显示当前/已读进度；不能依赖再次点击“下一章”才能刷新。
- 继续保留字符位置恢复、750 ms 去抖和章节变化/退出时的精确保存；恢复、字体变化、旋转屏幕、手动跳章和迟到回调不会互相覆盖。
- 离开阅读器应排空有效写入；加载、保存失败时保留可读内容和可重试操作，不能假装进入了未加载的章节。

### 字数进度

用户明确选择“本章字数进度，兼显章节位置”。显示当前章已读字数、当前章总字数和章内百分比，同时显示目录中的第几章/总章节数。显示字数按 Unicode 码点计数，换行和标点也作为正文字符一致计入，不把一个补充平面字符算成两个字。持久化与排版仍使用既有 UTF-16 字符偏移，不改变原存储契约；以当前偏移对应的正文前缀换算显示字数。全书正文未完整获得时，不把已缓存部分冒充全书总字数或精确全书百分比。字体、行距和分页变化不改变对应的正文位置。

## 3. 缓存、升级与用户数据

不要求卸载重装，不删除书架、来源映射、下载任务或阅读记录。已经存在的旧正文文件不能因为升级而静默整批删除。需区分经过新边界校验的独立章节内容与可能串章的旧缓存，防止更新代码后继续把旧混合正文作为正确的连续阅读输入。

对旧版合并正文中的位置，不能只按新正文长度截断后宣称原位置已正确迁移。旧记录先保留；可验证时才恢复到对应章节，无法精确还原时明确提示重新校验或选择真实章节，不猜测、不静默清零。联网重新抓取按章验证；失败不能销毁仍存在的旧文件。旧内容在离线条件下若不能保证章节边界，必须明确提示其限制，不能作为已经修正进度的证明。

如需新增内容格式标记或数据库字段，必须提供显式非破坏迁移与测试，保留已有主键、文件路径及用户记录，不允许 destructive migration。

## 4. 性能修复边界

优先消除一次切章误取多章、切章时取消后重新抓取同一预读请求，以及重复的非必要读取。已下载或缓存章节继续优先本地读取，读当前缓存不等待其他章的网络请求。

复用仍然有效的在途预读，并保持每次最多两章及现有移动数据选择。显式跳章、离开、删除、网络偏好改变仍能取消无意义工作。下载保持任务唯一性、限流、暂停恢复、世代检查和写入/删除屏障，不通过绕过这些保护换取表面速度。

默认自动缓存接下来的两章，进入新章后继续补齐后续两章；用户已有的关闭/一章/两章预读设置与移动数据选择仍然有效。缓存完成不等于读过，不能推进目录或阅读进度；预读失败不能挡住当前章的阅读。此次依次完成正文边界、旧内容校验、连续阅读与字数显示、预读复用，再另存经过审查的测试 APK。

用固定延迟的 MockWebServer 样本核对每章请求次数、在途请求是否复用，以及缓存读取是否独立；区分网络、解析、文件校验与持久化耗时。自动化证明减少重复工作，不承诺所有真实书源秒开。真实手机速度与书源可达性需用户再次测试。

## 5. 验证与交付

先证明失败，再修复并重跑。至少覆盖：下一章误作下一页、合法本章多页、目录 URL 边界、重定向/循环、两个阅读模式跨章标题与真实进度、预读不提前写进度、窗口追加不跳位、最后一章、加载失败/重试、手动选章、旋转/字体变化、旧回调、迟到写入、旧缓存及升级保存记录、缓存与在途请求复用。真实 HTTP/parser/repository/ViewModel 链路应有集成回归，不能只验证 mock 自身。

完整执行单元测试、lint、debug APK 构建与 Android-test 源编译；独立需求审查后再做质量审查。编译设备测试不代表已运行。主控上次 ADB 检查无设备；新的 APK 要另存文件、复核签名及 SHA-256，保留前两个测试包，标明测试版和未完成的真机/Release 验收。应用图标和应用内配色不变。
